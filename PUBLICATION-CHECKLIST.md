# Publication Checklist

Use this checklist before keeping this repository public, sharing it with employers, or linking it in a portfolio.

The goal is to make the repo look intentional, professional, safe, and useful.

---

## 1. Public Safety

```text
[ ] No API keys
[ ] No tokens
[ ] No passwords
[ ] No private client information
[ ] No private project links
[ ] No personal information that should stay private
[ ] No raw messy notes that should stay private
[ ] No copied private content from paid courses, clients, or companies
```

---

## 2. Professional Presentation

```text
[ ] README clearly explains why the repo exists
[ ] README explains who the repo is for
[ ] README shows the main workflow
[ ] README explains tool roles
[ ] README explains how to use the repo in Cursor
[ ] Repository structure is easy to understand
[ ] License exists
[ ] File names are clear
```

---

## 3. Portfolio Value

```text
[ ] Repo demonstrates planning discipline
[ ] Repo demonstrates specification-first thinking
[ ] Repo demonstrates testing awareness
[ ] Repo demonstrates security awareness
[ ] Repo demonstrates documentation habits
[ ] Repo demonstrates AI workflow maturity
[ ] Repo does not overclaim expertise
```

---

## 4. Content Quality

```text
[ ] Language is clear and beginner-friendly
[ ] No contradictory workflows
[ ] Spec Kit is always before Cursor implementation
[ ] CodeRabbit is always after implementation review
[ ] TestSprite is always after implementation QA
[ ] Checklists are practical
[ ] Templates are reusable
[ ] Prompts are specific enough to use
```

---

## 5. Maintenance

```text
[ ] PROJECT-CONTEXT.md is updated when major decisions change
[ ] README is updated when important files are added
[ ] manifest.json is updated when structure changes
[ ] Examples are improved as real projects are built
[ ] Outdated tool assumptions are reviewed periodically
```

---

## Final Question

Before sharing this repo, ask:

```text
Would I be comfortable if an employer opened this repository during an interview?
```

If the answer is yes, the repo is ready to share.
