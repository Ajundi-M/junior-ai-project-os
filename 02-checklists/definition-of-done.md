# Definition of Done

Use this before accepting a feature or project.

---

## Feature Definition of Done

A feature is done only when:

```text
[ ] Feature has a clear specification if Level 2+
[ ] Feature has a technical plan if Level 2+
[ ] Feature was broken into small tasks before implementation
[ ] Feature works locally
[ ] Code matches the acceptance criteria
[ ] Code is readable
[ ] No obvious duplication
[ ] Inputs are validated
[ ] Loading state exists if needed
[ ] Empty state exists if needed
[ ] Error state exists if needed
[ ] Mobile layout works
[ ] Auth checks exist if needed
[ ] Database access rules are correct if needed
[ ] No secrets are exposed
[ ] Manual testing passes
[ ] Important tests added if needed
[ ] CodeRabbit major/security issues fixed or consciously rejected
[ ] TestSprite main journey passes if relevant
[ ] Documentation updated if needed
[ ] I can explain what changed and why
```

---

## Project-Level Spec Checks

Use these before coding serious work:

```text
[ ] Level 1 uses at least a lightweight manual spec if the feature is more than a tiny change
[ ] Level 2 features have a written Spec Kit specification, plan, and task list
[ ] Level 3 features have a written Spec Kit specification, plan, and task list
[ ] Level 4 features have a written Spec Kit specification, plan, and task list
[ ] Any requirement change updates the spec before more implementation
```

---

## Project Definition of Done

A project is done only when:

```text
[ ] Main features completed
[ ] Level 2+ features are traceable back to specs
[ ] App deployed
[ ] Main user journeys work in production
[ ] README completed
[ ] Architecture notes completed
[ ] Setup instructions completed
[ ] Screenshots added
[ ] Demo account added if useful
[ ] Known limitations documented
[ ] Future improvements documented
[ ] Security checklist completed
[ ] Testing checklist completed
[ ] CodeRabbit has no unresolved critical issues
[ ] TestSprite validates main user journeys
[ ] Portfolio writeup completed
```
