# Testing Prompts

Use these for manual tests, automated tests, and TestSprite preparation.

Testing should be based on the acceptance criteria from the Spec Kit specification.

---

## Manual Testing Plan

```text
Create a manual testing checklist for this feature.

Use the acceptance criteria from this specification:
[paste acceptance criteria]

Include:
- happy path
- invalid input
- empty state
- loading state
- error state
- mobile behavior
- auth behavior
- refresh/reload behavior
```

---

## Test Cases

```text
Create test cases for this feature.

Use this feature specification as the source of truth:
[paste feature specification]

Separate them into:
1. Unit tests
2. Integration tests
3. E2E/user journey tests
4. Edge cases

Explain which tests are required for this project level and which are optional.
```

## Analyze TestSprite Failures

```text
[paste report]

1. Explain the failures in simple language.

3. Identify likely root causes.
4. Compare failures against the feature acceptance criteria.
5. Suggest exact fixes.

```
